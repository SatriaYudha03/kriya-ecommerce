## Konteks

Audit `docs/ec-v2/AUDIT-F1-A1D1-2026-09-26.md` menandai B1 "bersih dari
pelanggaran kepemilikan" — benar, B1 tidak pernah menulis ke file domain lain
atau file core. Tapi seperti A1/C1/D1, worktree-nya dibuat sebelum 0C's kode
asli benar-benar di-merge ke `main` (lihat AUDIT §0), jadi diperlukan review
ulang saat merge untuk menggabungkan tipe/fungsi baru ke modul yang sudah
dibuat 0C di `main`, bukan menimpa/duplikasi.

Ditemukan dua penyimpangan nyata dari kontrak yang perlu diperbaiki saat
merge (bukan pelanggaran kepemilikan, tapi pelanggaran kontrak §5):

1. `lib/customer/api.ts` versi asli B1 memakai `fetchWithAuth` buatan sendiri
   (fetch + `supabase.auth.getSession()` manual) alih-alih `request()` dari
   `lib/http.ts` yang wajib dipakai semua domain (§5.1: "fungsi fetch domain —
   wajib lewat lib/http.ts"). Diperbaiki: semua fungsi alamat/provinsi baru
   memakai `request()`.
2. `components/kriya/customer/address-picker.tsx` versi asli B1 mengubah
   signature stub §5.3 yang beku dari `{ value: string | null; onChange:
   (address: Address) => void }` menjadi `{ selectedId?: string; onSelect:
   (address: Address) => void }` — pelanggaran R6. Diperbaiki: signature
   dikembalikan ke kontrak asli, implementasi (radio list alamat) tetap sama.
