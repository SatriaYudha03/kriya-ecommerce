## Perbaikan (Claude, 2026-09-26, sebelum F1 diklaim)

Duplikasi `Meta`/`Response`/`ErrorDetail`/`ErrorResponse` di 5 package domain
(`catalog`, `checkout`, `customer`, `promo`, `aftersales`) dihapus; semua sekarang
import dari `internal/httpx` sesuai kontrak §4.2.

Ditemukan saat mengerjakan ini (lebih luas dari permintaan lintas-domain di atas):
`promo/models.go` dan `aftersales/models.go` ternyata membawa **seluruh scaffolding
domain katalog/checkout** (`CartResponse`, `OrderResponse` generik,
`AdminCreateProductRequest`, dll — >200 baris) yang sama sekali tidak dipakai di
package masing-masing — kemungkinan hasil copy-paste satu template `models.go` ke
semua domain saat 0B tanpa disesuaikan. Dibersihkan:
- `promo/models.go` disisakan hanya `AdminStatsResponse` (satu-satunya tipe yang
  dipakai, oleh `stats_handler.go`).
- `aftersales/models.go` disisakan `ShippingAddressResponse`, `OrderItemResponse`,
  `OrderResponse`, `InternalOrderStatusResponse`, `AdminUpdateOrderStatusRequest`
  (dipakai `ToOrderResponse`/handler internal).
- `catalog` dan `checkout` **tidak** dibersihkan dead-code-nya — tipe-tipe itu
  genuinely dipakai di sana (domain aslinya).

Diverifikasi: `go build ./...`, `go vet ./...`, `go test ./...` (29 test) semua hijau
dari `services/api`.

**Temuan lama yang TIDAK diperbaiki di sini (pre-existing, di luar scope perbaikan
ini):** `any-check.sh` masih melaporkan `gin.H`/`map[string]interface{}` di
`catalog/admin_handler.go`, `checkout/payment_handler.go`, `aftersales/admin_handler.go`
— dikonfirmasi via `git show HEAD:<file>` bahwa baris-baris itu sudah ada sebelum
perbaikan ini. Perlu permintaan lintas-domain terpisah bila mau dibereskan.
