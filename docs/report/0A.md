## Catatan penting untuk gerbang G0 (Claude, sebelum apply ke DB dev)

- ⚠ **Verifikasi status RLS aktual** di DB dev sebelum `ENABLE ROW LEVEL SECURITY` (S14) —
  migrasi 008 mengasumsikan RLS belum aktif di 10 tabel lama; kalau ternyata sudah ada
  policy custom, `ENABLE ROW LEVEL SECURITY` tanpa policy akan MENGUNCI akses PostgREST
  ke tabel itu untuk semua role kecuali service_role. Jalankan dulu:
  `SELECT tablename, rowsecurity FROM pg_tables WHERE schemaname='public';`
- ⚠ **`SELECT DISTINCT status FROM orders;`** sebelum menerapkan `orders_status_check` — kalau
  ada nilai status di luar 8 yang diizinkan, migrasi 008 akan gagal di constraint itu.
- ⚠ **`orders_money_check`**: uji dulu `SELECT count(*) FROM orders WHERE total <> subtotal + shipping_cost;`
  (formula lama, sebelum discount_total/shipping_discount ditambah dengan default 0) — kalau ada
  order dengan data tidak konsisten, constraint baru akan menolaknya saat migrasi diterapkan.
- ⚠ **`product_variants_money_check`**: uji dulu `SELECT count(*) FROM product_variants WHERE price <= 0 OR stock < 0;`
  — kalau ada baris begini di data produksi, migrasi 009 akan gagal.
- Kode 38 provinsi disalin dari RENCANA §5.3 apa adanya, **belum di-cross-check ulang** ke
  sumber Kemendagri/BPS terbaru (tidak ada akses internet di sesi 0A). Risiko rendah — lihat
  Permintaan lintas-domain di `docs/ec-v2/LOG-0A.md`.
- Seed ongkir §5.3.1 di RENCANA hanya berbentuk tabel markdown, bukan SQL — saya tulis sebagai
  INSERT eksplisit di `010_customer_checkout.sql`. Nilai (base_cost, per_kg_cost, dst.) persis
  menyalin angka di tabel itu; ini "angka contoh" per catatan RENCANA, admin bisa ubah dari UI
  setelah B4 (task ongkir tabel) selesai.
- Migrasi ini **tidak** membersihkan atau mengubah `carts.items`, `profiles.address_line/city/
  province/postal_code`, atau `orders.shipping_zone` — hanya ditandai `DEPRECATED` via `COMMENT
  ON COLUMN` sesuai D12. Penghapusan menyusul migrasi 013+ setelah Satria setuju.
