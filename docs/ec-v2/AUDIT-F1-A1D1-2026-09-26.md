## 1. Temuan #1 (paling kritis): `check-ownership.sh` selalu lulus, tidak pernah memvalidasi

### Apa yang terjadi
```bash
$PY - "$AGENT" "$OWNERSHIP_FILE" << 'EOF'
...
changed_files = sys.stdin.read().splitlines()
...
EOF
```
Heredoc `<< 'EOF' ... EOF` dipakai untuk mengirim **source code Python** ke stdin
proses `python -` (mode baca script dari stdin). Begitu Python selesai membaca
heredoc sebagai script, stdin sudah habis. Baris `sys.stdin.read()` **di dalam**
script yang sama itu kemudian membaca stdin yang sama — yang sudah kosong. Hasilnya
`changed_files = []` **selalu**, apa pun isi `git diff` yang sebenarnya. Loop
validasi tidak pernah punya data untuk diperiksa, `violations` selalu kosong, skrip
selalu mencetak `"Ownership check passed for agent X."`.

### Dampak
Setiap baris "check-ownership.sh: LULUS" di `docs/report/*.md` dan `docs/ec-v2/STATUS.md`
sebelum commit `e7ad5d6` (2026-09-26) — termasuk 0A, 0B, 0C, 0D, A1, B1, C1, D1 —
**tidak pernah benar-benar tervalidasi**. Ini baru ketahuan saat review manual A1
menemukan pelanggaran kepemilikan besar (76 file) padahal skrip bilang "passed".

### Perbaikan yang sudah dilakukan
Commit `e7ad5d6` (main): daftar file berubah ditulis ke file sementara lalu
dilewatkan sebagai **argumen CLI** ke skrip Python (`sys.argv[3]`), bukan lewat
stdin yang bentrok dengan heredoc. Sudah diverifikasi: re-run terhadap A1
menghasilkan 76 pelanggaran nyata (sebelumnya 0).

### Yang masih perlu dilakukan
- Re-audit `docs/report/0A.md` … `0D.md`: baris "check-ownership.sh lulus" di sana
  perlu ditandai "tidak tervalidasi (bug), belum direview ulang" sampai ada yang
  benar-benar menjalankan skrip yang sudah diperbaiki terhadap branch-branch itu
  (kalau branch masih ada / belum dihapus).
- Tambahkan unit-test kecil untuk `check-ownership.sh` sendiri (mis. kasus sintetis:
  1 file yang jelas milik agent lain → harus exit 1) supaya regresi seperti ini
  langsung ketahuan, bukan menunggu audit manual lagi.
